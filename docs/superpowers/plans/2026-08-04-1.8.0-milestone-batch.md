# 1.8.0 Milestone Batch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land issues #648, #645, #649, #663, #644, #656, #646 as separate commits on `dev/1.8.0`, verify #637 via the end-of-batch CATS campaign, bump to 1.8.0, and open one PR.

**Architecture:** Server-side Go changes in the `api/` and `auth/` packages plus OpenAPI spec additions. Spec is source of truth: every spec edit is followed by `make validate-openapi` and `make generate-api`. Sort-stability and quota-default fixes touch GORM stores (Oracle review required at the end). New admin endpoints ride the existing declarative `x-tmi-authz` authorization.

**Tech Stack:** Go, Gin, GORM, oapi-codegen v2 (pinned v2.7.1 global binary), kin-openapi, testify, SQLite-backed unit tests via make targets.

## Global Constraints

- MANDATORY: only `make` targets for build/test: `make lint`, `make build-server`, `make test-unit`, `make test-unit name=TestName`, `make validate-openapi`, `make generate-api`. Never `go test` / `go run` directly.
- Never use the standard `log` package; use `github.com/ericfitz/tmi/internal/slogging`.
- Never use generated `FromNode`/`MergeNode`-family methods (not relevant to these tasks, but absolute).
- Every status code a handler returns must be documented in the spec for that operation.
- Spec naming: JSON properties `snake_case`, params `snake_case`, schemas `PascalCase`, operationIds `camelCase`.
- SEM markers: every new/behavior-changed function gets a `// SEM@<sha>: <intent>` one-liner (finalization runs `/sem-annotate --update` on changed files; implementers should still write a plain `SEM@0000000:`-style placeholder marker line so the annotator has intent text to refresh — or simply write the marker with the current short sha of HEAD).
- Commit after each task with a conventional message referencing the issue.
- `api/api.go` is generated — never hand-edit; regenerate via `make generate-api`.
- The OpenAPI JSON is >100KB: edit with `jq` against a backup, or with careful `Edit` on exact unique strings; validate with `jq empty api-schema/tmi-openapi.json` and `make validate-openapi` after every spec change.
- Adding a new `/admin/*` operation without `x-tmi-authz: {"ownership":"none","roles":["admin"]}` fails `TestAdminRoutesDeclareAdminRole`.
- Adding response examples: `make check-response-examples` gate exists; new operations' 200/201 examples must cover every key the server returns (see #637) or be omitted entirely — prefer **exhaustive examples or none**.

```go
type samlMatchType int

const (
	samlMatchProviderID samlMatchType = iota
	samlMatchLinkedIdentity
	samlMatchProviderEmail
	samlMatchEmailOnly
)

// SEM@<sha>: apply guarded tier-aware profile updates to a matched user on SAML login (reads DB)
func updateSAMLUserOnLogin(ctx context.Context, r samlUserResolver, user User, userInfo *saml.UserInfo, match samlMatchType) (*User, error) {
	logger := slogging.Get()
	now := time.Now()
	user.LastLogin = &now
	user.ModifiedAt = now

	if userInfo.Name != "" && !userInfo.NameSynthesized && user.Name != userInfo.Name {
		logger.Info("Updating user name from SAML assertion: %s -> %s", user.Name, userInfo.Name)
		user.Name = userInfo.Name
	}
	// Email only on the strongest tiers; email-tier matches matched BY email, and a
	// synthesized email must never replace a real one.
	strongMatch := match == samlMatchProviderID || match == samlMatchLinkedIdentity
	if strongMatch && userInfo.Email != "" && !userInfo.EmailSynthesized && user.Email != userInfo.Email {
		logger.Info("Updating user email from SAML assertion: %s -> %s", user.Email, userInfo.Email)
		user.Email = userInfo.Email
	}

	if err := r.UpdateUser(ctx, user); err != nil {
		return nil, fmt.Errorf("failed to update user: %w", err)
	}
	return &user, nil
}
```
