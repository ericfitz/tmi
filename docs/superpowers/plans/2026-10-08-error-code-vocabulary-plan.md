# Error Code Vocabulary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the server emit only the 21 documented REST error codes (plus the protocol set on OAuth/SAML routes), document them as enums in the OpenAPI spec, and add gates that fail when code and spec drift (#1048).

**Architecture:** A leaf package `internal/errcode` holds every code as a typed constant and the three sets. `api/request_utils.go` constructors are the only way handlers build `RequestError`s; domain reasons move to `details.code`. A `go/ast` lint rejects string-literal codes, and a unit test ties the constant sets to the spec enums. One PR, non-breaking title (`feat(api): adopt one documented error-code vocabulary`), never edits `.version`, `api/version.go` or `info.version`.

**Tech Stack:** Go 1.2x, Gin, oapi-codegen v2.7.1 (`make generate-api`), jq, uv/Python lint runner (`scripts/lint.py`), Make targets only.

**Spec:** `docs/superpowers/specs/2026-10-08-adr-error-code-vocabulary.md` (the ADR; copy it from the scratchpad into the repo in Task 1). Proposal with the full inventory: `scratchpad/1048-proposal.md`.

## Global Constraints

- Never run `go test`, `go run` or `./bin/tmiserver` directly; use `make test-unit name=TestX count1=true`, `make lint`, `make verify`, `make validate-openapi`, `make generate-api`, `make test-integration`.
- Never edit `api/api.go` by hand; it is regenerated by `make generate-api` with oapi-codegen v2.7.1 exactly (other versions miscompile it). Never edit `info.version`.
- Never call the generated `FromNode`/`MergeNode` helpers (unrelated, but `make lint` enforces it).
- HTTP status codes of existing responses do not change. A rename changes only the `error` string (and may add `details.code`).
- Logging goes through `internal/slogging`; never `log` or `fmt.Println`.
- Use American English. Conventional commits. Commit after every task.
- Branch: `dev/<next>/1048-error-vocabulary` off `main`. Work in a worktree.
- Every `SEM@` marker on a function whose behavior changed is refreshed with `/sem-annotate --update <files>` before the final commit.

## Review Focus

1. A handler that builds `Error{Error: "..."}` through a helper not covered by the lint (variables, `fmt.Sprintf`): Task 5's lint test includes a variable-passing fixture and the drift test in Task 3 catches spec-side gaps.
2. A 401 from the identity-link flow losing its `WWW-Authenticate` behavior when moved to `UnauthorizedError`: Task 11 keeps the `gin.H` status and adds a test asserting status 401 and `details.code = invalid_token`.
3. Protocol routes receiving Tier 1 codes from middleware (`unicode_validation_middleware.go` path switch): Task 10 adds a test that `/oauth2/token` still gets `invalid_request` and `/threat_models` gets `invalid_input`.
4. `admin_quota_handlers.go` bodies that previously had no `error_description`: Task 9 asserts both fields are present and non-empty.
5. Spec examples: an example `error` that is a sentence or `unprocessable_entity` under the new enum fails `make validate-openapi`; Task 2 fixes all of them before regenerating.
