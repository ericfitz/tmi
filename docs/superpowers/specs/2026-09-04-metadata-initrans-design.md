## Design (approved 2026-09-04, human decision) — folds in #784

**Context that changed since filing:** the 503 was fixed in #801 (BulkReplace opted down to READ COMMITTED, where Oracle never raises ORA-08177). INITRANS is now defense-in-depth for the ten `deleteAndSaveEntityMetadata` callers (`api/metadata_helpers.go:93`) that still run inside SERIALIZABLE parent transactions. Separately, no code reads metadata by `created_at` or `modified_at` (every read orders by `key` or `(entity_type, entity_id)`), so the four timestamp indexes, the hot-leaf-block aggravator, are dead weight.

1. **Drop the four dead timestamp indexes** (`idx_metadata_created`, `idx_metadata_modified`, `idx_metadata_entity_created`, `idx_metadata_entity_modified`): remove the tags from `models.Metadata` (`api/models/models.go:552`) and add an ensure-step `DropRetiredMetadataIndexes` in `internal/dbschema`, because AutoMigrate never drops indexes. PostgreSQL: `DROP INDEX IF EXISTS`. Oracle: probe `ALL_INDEXES` with the `SYS_CONTEXT('USERENV','CURRENT_SCHEMA')` owner predicate (`catalog_probe.go:37`, never `USER_*`), drop what exists via `execMigrationDDL`. This closes #784.
2. **Raise INITRANS to 16 on METADATA and its six surviving indexes** (Oracle only): ensure-step `EnsureMetadataInitrans` on the `EnsureUserProviderLookupUnique` template (`user_identity_index.go:67`): probe `ALL_TABLES.INI_TRANS` / `ALL_INDEXES.INI_TRANS`, skip when already at target, else `ALTER TABLE METADATA INITRANS 16`, `ALTER TABLE METADATA MOVE ONLINE` (existing blocks get the slots), then `ALTER INDEX <name> REBUILD ONLINE INITRANS 16` per surviving index (PK index, `idx_metadata_unique`, `idx_metadata_entity_type_id`, `idx_metadata_entity_id`, `idx_metadata_key`, `idx_metadata_key_value`). Re-probe after DDL rather than trusting the error; on failure log ERROR and return nil so the next boot retries. All DDL through `execMigrationDDL` / `withDDLRetry`.
3. **Wiring:** both steps in the unconditional post-AutoMigrate tail (outside the #480 fingerprint fast path) at all three call sites: `cmd/server/main.go` `runMigrationsLocked`, `auth/config_adapter.go`, `cmd/dbtool/schema.go`. Drop runs before INITRANS. All three already hold the advisory migration lock.
4. **Acceptance:** the OCI integration test (`api/metadata_bulk_oracle_test.go`, `//go:build oracle`, `make test-integration-oci`) gains a catalog probe asserting `INI_TRANS >= 16` on the table and every surviving index and that the four retired indexes are absent. No dbtool command added. The back-to-back BulkReplace test already asserts plain success and is unchanged.
5. **Not doing:** the other seven delete-then-insert tables (project/team responsible parties, relationships, members, survey_answers, timmy_embeddings) have 2-3 indexes and no timestamp index, so no aggravator; untouched. Batching `saveEntityMetadata`'s per-key inserts (review note from #841) stays a separate perf item.
6. **Oracle review** mandatory for both steps; reviewer to confirm `MOVE ONLINE` on ADB 23ai is supported and index-maintaining.
